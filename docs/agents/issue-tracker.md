# Issue tracker

GitHub Issues at `ZF-IT-Automation/tim` is the public, shared tracker. Use it via `gh`. Inbound reports land there.

## Default

- `to-spec` and `to-tickets` publish with `gh issue create`. Write multi-line bodies to a temporary UTF-8 file and pass `--body-file`.
- Write blockers as `Blocked by #N` lines in the body. Label agent-ready tickets `ready-for-agent`.
- `triage` works the open issues: `gh issue list --state open`, `gh issue view <N> --comments`.
- Close with the fixing commit: the message ends with `Fixes #N`. The default branch is `master`; `Fixes #N` closes the issue only once the commit reaches it. If the issue is still open after the push, run `gh issue close <N> --comment "Fixed in <sha>"`.
- Rejected or already built: add `wontfix`, post a reason comment, run `gh issue close <N> --reason "not planned"`.

## Optional personal routing

- If your own global agent instructions define a personal tracker for your own work, you may follow them for your own work. Example: TIM, the memory system this repo builds, with a project bound to your checkout via a gitignored `.tim-project` marker.
- Then mirror an accepted issue (`ready-for-agent` / `ready-for-human`) into the personal tracker. Dedupe first. The body carries `Source: <issue URL>`. The agent brief lives in the personal tracker.
- GitHub keeps the state and category labels plus one short accepted comment.
- The GitHub issue stays the public record. Close it with the fixing commit as above. Never leave an accepted issue without a closing reference.
- A rejected mirrored issue is also cancelled in the personal tracker.

## Rules

- Everything posted to GitHub during triage starts with `> *This was generated by AI during triage.*`.
- Pull requests are not a triage input.
- Labels are the default strings: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`; categories `bug`, `enhancement`.
- As of 2026-10-09 the repo has only `bug`, `enhancement`, `wontfix`, `ready-for-agent`. `triage` creates a missing label with `gh label create` on first use.
- Publishing children never closes or edits the parent (spec, map, GitHub issue).
